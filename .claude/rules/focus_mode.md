# Focus Mode — Mid-Task Interruption Handling

When the user sends a message **mid-task** — at least one tool call made on the current task, its final
result not yet reported — and it is not an answer to a question you asked, run the **focus-mode** skill
before you continue. In short:

- **A complaint about how the work is going** ("you're doing nothing", "this is taking long", "why can't you
  just answer") → name what went wrong in one line and change course now. Ask only if you still cannot tell
  what the objection is — and then about the objection, never a menu of artifacts.
- **Correction signals** ("wait", "no", "stop", "not that") → acknowledge in one line and ask whether it is a
  real interrupt.
- **Input that bears on the work in flight** (unsure → treat it as this) → take it into the work and say so;
  if it changes the scope, surface it and wait. **Never auto-note it.**
- **Only a genuinely unrelated thought** → capture it with the **note** skill and continue.
- **The clarify skill always stops you.**
